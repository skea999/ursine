# SPEC-booster

## Objective

Module **`booster`** (user decision 2026-11-10: the module is called
`booster`, not `initramfs`). Manage the **booster** initramfs generator: edit `/etc/booster.yaml` and
regenerate the initramfs by running the distribution's own kernel-update
process. Booster-only (user decision 2026-11-10): no mkinitfs,
update-initramfs, dracut or mkinitcpio paths — other distros work only where
booster is installed. Reference distro: FeralOS (Alpine-based; boot flow in
its `src/chrootPhase/internal/boot.go`).

## API surface

| Action | Backend |
|---|---|
| `booster_config_get` | parse `/etc/booster.yaml` → raw text + typed known keys |
| `booster_config_set` | surgical line edit of known keys → `backup_configs` rotation → whole-result YAML parse validation → atomic tmp+rename (0644) |
| `booster_regenerate` | chain below, root, captured stdout/stderr, timeout 120 s |

### Regenerate chain (FeralOS first, never guessed paths)

1. **`apk fix kernel-hooks`** — when `apk` exists AND
   `/etc/kernel-hooks.d/` contains at least one `*.hook` AND the
   `kernel-hooks` package is installed (`apk info -e kernel-hooks` — the
   manual re-run needs it). On FeralOS this
   runs `50-booster.hook` (`booster build --force --kernel-version
   "${NEW_VERSION}-${FLAVOR}"` + `efi-mkuki` UKI + backup + `BOOTX64.EFI` +
   `/boot/efi2` mirror) — exactly what the kernel update does. Hook args
   (`flavor`, `version`) come from the kernel-hooks trigger.
2. **fallback = booster build** (only when step 1 does not apply):
   - `/usr/lib/booster/regenerate_images` if present (distro helper — same
     family, correct naming), else
   - `booster build --force --kernel-version <K>` for every
     `/lib/modules/*`, output `/boot/booster-<flavor>` (flavor = part after
     the last `-`, Alpine/FeralOS convention). If the naming cannot be
     derived → `Unavailable` with a clear message; never a guessed path.
3. No booster, no hooks, no apk → `Unavailable` with `apk add booster`.

The response reports which step ran plus the merged stdout/stderr (the apk
step surfaces every hook's own output, e.g. `executing hook 50-booster.hook
(virt, 6.6.7-0, )`). Not a package mutation → plain action, no job log.

### Config edit rules

- File edit is justified: booster has no configuration CLI (same rule as
  themes). No D-Bus, no polkit (invariants 2–3).
- Known keys only (surgical, line-based): `compression`, `universal`,
  `strip`, `vconsole`, `enable_lvm`, `enable_mdraid`,
  `append_all_modaliases`, `mount_timeout`, `token_timeout`, `pin_delay`,
  `extra_files`, `modules`, `modules_force_load`, and
  `network.{dhcp,ip,gateway,dns_servers,interfaces}`.
- Comments, unknown keys and the `# Generated by FeralOS Installer` marker
  stay byte-identical (flatpak-keyfile spirit: we own our keys only).
- Write order: `backup_configs` rotation (uniform `.ursine-backup[.N]`
  slots) → validate the complete new text parses as YAML → atomic replace.
- `booster_config_set` never rebuilds; Regenerate is a separate action.

## Capability

- Single capability **`Booster`**: probe the `booster` binary (candidate
  absolute paths), fix hint `apk add booster`. Gates the module, both config
  actions and regenerate; Home shows the fix row on the activated feature
  when missing. Without booster the module is unavailable — by design.

## GUI

- Sidebar **Booster** (initramfs section).
- Config: typed rows for the known keys (checkboxes for booleans,
  text/dropdown for the rest) + raw view of the file; **Save** (confirm
  names the file and the rotation) writes via `booster_config_set`.
- **Regenerate** button with Cockpit-style confirmation naming the step
  that will run (`apk fix kernel-hooks` or the booster build fallback);
  output shown in the terminal-style box (monospace, snap-to-bottom) with
  the step banner as the first line.
- Capability-gated: without `booster` the section shows the
  `apk add booster` fix row (Home pattern).

## CLI (parity, same task)

- `ursinectl booster get` — raw + typed keys (`--json` for scripts).
- `ursinectl booster set key=value …` — surgical update of known keys;
  unknown keys rejected (same rejection style as the generic surface).
- `ursinectl booster regenerate [--yes]` — confirmation gate for the
  rebuild; prints the step banner then the captured output; exit code
  follows the action result.
- `docs/guides/ursinectl.md` and `packaging/man/ursinectl.1` updated in
  the same task (parity rule).

## Testing

- Unit: surgical edit preserves comments/marker/unknown keys (including
  inline hash comments after the value, blank lines inside `network:` and the installer
  marker); empty/`#`-shaped/newline values rejected; unknown `clear` keys
  rejected; empty patch is a byte-exact no-op; flavor/naming derivation
  refuses digit-only or implausible suffixes (never a guessed path);
  capability probe absent → Unavailable with `apk add booster`.
- Chain selection reads live paths (`/etc/kernel-hooks.d`,
  `/usr/lib/booster/regenerate_images`, `/lib/modules`), so the full
  order is exercised in the VM smoke below; `select_step()` is the single
  source of truth for both the confirm-dialog preview and the run.
- Samples/drift guards + CLI module sweeps (reads Ok, regenerate Skip in
  CI — it would really rebuild).
- `cargo test --workspace --all-features`; static gate unchanged.

## VM smoke (FeralOS or Alpine + booster + kernel-hooks)

- Edit a key → Save → file keeps comments/marker; `*.ursine-backup` slot
  exists; Regenerate shows hook output, UKI rebuilt under
  `/boot/efi/Alpine/linux-<flavor>.efi`, backup + `BOOTX64.EFI` updated.
- Forced `booster build` failure (bad key) keeps the previous image.
- Non-booster box: module unavailable with `apk add booster`.
