# Ursine project invariants (binding for every agent)

Read `docs/architecture/overview.md` before any code change. Never violate these:

1. **Memory-safe Rust only.** No `unsafe` blocks unless discussed and approved explicitly.
2. **No polkit.** Auth = PAM handshake (feature `pam`) once per session + RAM-only session tokens. Never write tokens to disk, never store secrets in frontends.
3. **No D-Bus. Ever.** Ursine never speaks D-Bus (our code never links `zbus` or `dbus-send`, never runs `gsettings` over the session bus; libcosmic may pull `zbus` transitively — that dependency is theirs, documented in `docs/static-analysis-exceptions.md`). Operate on system files directly — the Webmin pattern (`/etc/passwd`, `/etc/shadow`, `/etc/group` … read/parse/write yourself) — or through system CLIs (`nmcli`, `bluetoothctl`, `firewall-cmd`, `useradd` …). A system CLI may use D-Bus internally; that is its component, never ours. Fewest components possible: Ursine is the GUI over the commands you would type.
4. **No database. Ever.** The daemon is stateless; system state is read live from apk/flatpak/nix/shadow/btrfs. Audit = JSONL append-only. Config = `/etc/ursine/config.toml` (tri-state `"auto"|true|false`).
5. **Capabilities are runtime-detected**, never persisted. `ensure_available()` before every module action. A capability names the exact CLI its module runs, and its fix hint is the exact install command for that binary (e.g. Disks → `apk add parted …`); the Home screen shows that fix on every activated feature whose capability is missing.
6. **musl everywhere**: local builds via Docker with Alpine Linux images; CI builds musl; the nix flake must use musl (pkgsMusl/pkgsStatic), never glibc.
7. **`asUser` discipline**: `flatpak --user` and `nix profile` run as the target user; `apk` and flatpak `--system` are always root. Never mix scopes.
8. **Frontends are thin**: no logic in GUI (`ursine`) or web (`web/`). All logic lives in `ursined` / `ursine-core`. Shared types only via `ursine-api`.
9. **Protocol**: newline-delimited JSON over unix socket; Bearer token on every request after handshake.
10. **CI requirements**: GitHub Actions must build + test every cargo feature combination (musl) and build + publish the nix flake.
11. **Vocabulary**: use `CONTEXT.md` terms exactly (module vs feature vs capability, principal, session token, asUser).
12. **Session protocol**: at session start read `handoff/latest.md` + `state/session-state.json`; at session end update them + `docs/TASKS.md`.
13. **HOST ISOLATION (absolute)**: never modify the host machine — no installs, no nix gc/profile changes, no global tooling, no system commands. ALL builds, tests, dedup, security checks, dependency checks and maintenance run inside Docker containers (alpine for cargo, nixos/nix for flake). Container volumes: project root mounted READ-ONLY, only `artifacts/` writable. Temp files NEVER in host `/tmp` — always `artifacts/<tool-or-task>/` (gitignored). Keep only the last 3 artifact versions per subfolder. Host nix store GC only via the nixos/nix container, never with `-d`.
14. **Language**: everything written in this repo (code, docs, scripts, comments, commits) is ENGLISH only.
15. **Conventions**: change logs go to `CHANGELOG.md` (never AGENTS.md/handoff). Agents stay FLAT in `.opencode/agents/` (nested pack dirs do not load — after any installer run, re-promote new agents to flat).
16. **Frontend/backend parity**: implement every function in the daemon first, then in every frontend immediately, within the same feature: GUI (`ursine`) and CLI (`ursinectl`). Never close a feature with a daemon action that has no GUI control and no CLI subcommand. No new feature until daemon and every frontend reach functional parity. Deferral requires explicit user approval recorded in `state/session-state.json`.
17. **UI references**: take interaction and layout inspiration from `cosmic-settings` (native COSMIC structure), Webmin (dense module/action coverage), Cockpit (capability gating, status visibility, destructive confirmations). Copy patterns, not code; Ursine terminology and thin-frontend rules win.
18. **Static analysis (binding)**: build/test/static commands are canonical in `docs/guides/build-and-test.md`; static policy and gates in `docs/STATIC-ANALYSIS.md`; all of it runs in containers (`ursine-ci:1`, `ursine-static:1`, `nixos/nix`). `scripts/static-check.sh` is the single static entry point. Product code lives under `src/` (crates, `src/tools/`, `src/web/`); dev/CI tooling stays in `scripts/`.
19. **Review closure**: fix every confirmed review finding — blocker, high, medium and low — before commit. Zero known defects at commit time. Never silently downgrade or defer a finding; a deferral needs explicit user approval recorded in `state/session-state.json` with owner and rationale. A fix cycle revalidates the full gate, and findings introduced by a fix count as new defects.
